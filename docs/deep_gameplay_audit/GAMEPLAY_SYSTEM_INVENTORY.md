## 1. Quy ước phân loại bắt buộc

Mọi hệ thống dưới đây được gắn **hai nhãn độc lập**:

1. **Bản chất logic hiện tại:**
   - **Gốc đã khôi phục:** Đọc đúng bảng VN gốc và thực thi đúng luật client/server gốc.
   - **Tái dựng có căn cứ:** Dựa trên bảng VN gốc, phần server không có trong APK được suy luận có bằng chứng.
   - **Mô phỏng / Hardcode:** Dùng công thức/pool thay thế hoặc bỏ qua bảng config đã có sẵn.
   - **Chưa triển khai:** Có UI/config/RPC client nhưng backend chưa có handler hoặc chỉ trả stub.
   - **Chưa đủ bằng chứng:** Chưa xác định được nguồn gốc hoặc công thức server gốc.

2. **Mức độ khả năng phục hồi (A / B / C / D):**
   - **A — Khôi phục trực tiếp:** Có đủ config VN + hợp đồng RPC/UI client, chủ yếu thiếu nối backend hoặc đọc thiếu trường.
   - **B — Tái dựng có căn cứ:** Có config VN cốt lõi, cần suy luận thêm luật server (ví dụ AI, tỉ lệ drop server-side, tạo đội hình).
   - **C — Mô phỏng hợp lý:** Thiếu dữ liệu/dịch vụ server gốc (multiplayer, roster wave gốc, tỉ lệ gacha server-side), cần giải pháp thay thế có kiểm soát.
   - **D — Chưa đủ bằng chứng:** Thiếu dữ liệu/nguồn xác thực (ví dụ nguồn cấp món Trang Bị Kim đầu tiên trong VN, trọng số FAP thứ cấp bậc cao).
